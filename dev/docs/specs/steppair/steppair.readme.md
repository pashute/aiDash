# Vocabulary
- HumandAI - The development assistant AI and the developer team to help each other complete what the other lacks. The human with reality checks and breaks,  and better access to realtime and real information. The AI with wider and faster preconcieved knowledge. 

- Specsdev (Development by Specifications) - is a systematic development system for a HumandAI team working according to specifications listed by the HumandAI in the Github-Project V2 project-management system, for developing with TDD BDD and DDD methodologies and Gitflow. This system slows the pace to fit for human scrutiny, and allows the AI to leap ahead when in correct direction, turning the development process into  steerable and reliable.

- DynamaiT (Dynamic AI Tasks) - a systematic way for a human to instruct an AI to create tools, and for the AI to present tools it uses, where natural language replaces coding. This is based mainly on action traceability and planning along with stop-points for HumandAI alignment and testing.

Programs created with DynamaiT can be much more flexible than coded programs, and include self-evolving sections, dynamic open end junctions and self testing, while open to human scrutiny. DynamaiT is described in the Overstand patent listed in the pashute/OOWAA repo. 

- Aidash are interactive elements connecting a human user and an AI chat or agent and allowing them to interact in extra channels besides the chat. They are written with Dynamait, currently using some elements of Specsdev. 


# `steppair` Purpose: 

The `steppair` aidash assists the developer who is using the Specsdev package. It kicks in just before ending a Gitflow feature and shows the planned steps of a feature, compared to the actual steps taken. This allows the developer to easily see if all was done correctly, categorizing and pairing the actual steps taken, with the planned ones. The process is heavily assisted by the AI.
